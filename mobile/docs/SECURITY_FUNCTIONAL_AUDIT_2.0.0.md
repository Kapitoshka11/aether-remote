# Aether Remote 2.0.0 — проверка безопасности, функций и интерфейса

Проверка начата 5 сентября 2026 года. Область: нативный Android-клиент и выпускаемый Electron-хост Windows. Веб-превью, сайт, экспериментальная Rust/Tauri-версия не являются проверенными приложениями этого выпуска. Это инженерная проверка доступного исходного кода, зависимостей и воспроизводимых сценариев, а не гарантия отсутствия уязвимостей во всём продукте.

## Исправления

1. Android: кнопка настроек на экране подключения перекрывалась прозрачной областью прокрутки. Нативный тест на Android 15 воспроизвёл невозможность открыть настройки; после изменения порядка отображения тест прошёл.
2. Android: фон окна настроек пропускал текст нижележащего экрана. Добавлены плотный фон, ограничение ширины/высоты и прокрутка; заголовок не отбирает место у кнопки закрытия.
3. Android: нечисловое значение NaN отображалось ползунком Aether Deck. Теперь используется конечное безопасное значение без отправки команды при отрисовке. Новый тест сначала упал, затем прошёл.
4. Android: некорректный ожидаемый TLS-отпечаток интерпретировался как отсутствие закреплённого сертификата. Проверка теперь отклоняет его. Это усиление нижнего уровня: основной путь подключения уже проверял формат QR-отпечатка. Новый тест сначала упал, затем прошёл.
5. Android: внешний ACTION_SEND мог передать file:// URI для чтения от имени приложения. Общий загрузчик теперь допускает только внешний content://, отклоняет собственный FileProvider и URI с указанием пользователя. Метаданные и открытие файла выполняются на IO-потоке. Текстовое вложение с EXTRA_STREAM больше не теряется из-за MIME text/plain. Для общего текста действует лимит 100 000 символов.
6. Windows: точечно обновлены транзитивные fast-uri и @xmldom/xmldom. До обновления npm audit сообщил о двух уязвимых пакетах (high и moderate); после обновления — 0 известных уязвимостей.
7. Версии: Android versionName 2.0.0, versionCode 22; Electron package.json и package-lock.json — 2.0.0. Предыдущий файл «Aether Remote 1.7.0.apk» фактически содержал versionName 1.6.0 и versionCode 21. Теперь метаданные проверяются внутри APK.

## Проверки и доказательства

Первоначальный Android-прогон: 86 тестов, 3 падения. Два теста ожидали непрерывный ползунок, хотя рабочая реализация использует шаг 1 (99 внутренних шагов на диапазоне 0–100); ожидания приведены в соответствие с поведением без удаления проверок геометрии. Третий тест отправлял значение отсутствующему ползунку; в снимок добавлен настоящий ползунок и сохранены проверки ревизии и sequence. Защита от несуществующих элементов не ослаблялась.

Следующий регрессионный прогон: 24 теста, 2 ожидаемых падения новых проверок TLS и NaN. После исправлений полный локальный набор: 90 тестов, 0 failures/errors/skipped. Android lint: 0 ошибок, 74 предупреждения, преимущественно устаревшие API и рекомендации. Изначальный эмулятор LanePC не отвечал на запрос API Level; создан отдельный тестовый AVD Android 15 без изменения его пользовательских данных.

Windows: npm test завершился с кодом 0 до и после обновления зависимостей. Цепочка содержит 45 тестовых команд, включая Electron/Python runtime и настоящие Windows audio/media проверки. Это число команд, не выдуманное число отдельных assertions. npm run lint, npm run electron:build — код 0. Установщик имеет ProductVersion/FileVersion 2.0.0. В app.asar проверены версия package.json и побайтовое совпадение main.cjs с исходником. Authenticode-статус установщика: NotSigned.

Финальный общий Android-прогон (`verification-final-200.log`) завершился кодом 0: 90 локальных тестов прошли; устройство — 3 теста, 2 прошли, 1 пропущен, ошибок нет. Пропущенный HostConnectionTest затем отдельно успешно выполнен с настоящим Electron-хостом (`android-host-integration-200.log`): TLS с закреплённым отпечатком, подтверждение на ПК, синхронизация Deck, две передачи файлов с точной сверкой содержимого на Windows и отключение. Конфигурация подключения удалена после теста.

Упакованный хост из `dist_electron/win-unpacked` проверен отдельно (`packaged-runtime-retry-200.log`): весь runtime smoke прошёл. Первая попытка (`packaged-runtime-200.log`) дала тайм-аут MEDIA при одновременных тяжёлых Android-проверках. Повтор без изменения тайм-аутов теста прошёл; нагрузка считается вероятной причиной, а не доказанным объяснением. При повторяемом появлении задержки требуется отдельное профилирование.

Подпись Windows: NotSigned, хотя упаковщик пишет строки «signing with signtool». Эти строки не означают наличие сертификата издателя. Упакованный `main.cjs` побайтово совпадает с исходником. Контрольные суммы финальных файлов приведены в SHA256SUMS.txt в папке сборок.

## Подпись и ограничения выпуска

Обычная :app:assembleRelease завершилась кодом 1: отсутствуют KEYSTORE_PATH, STORE_PASSWORD, KEY_ALIAS и KEY_PASSWORD. Найден ранее использованный JKS, но его пароль недоступен. Секреты не выводились и новый ключ на замену не создавался.

Оптимизированный unsigned APK собирается отдельной временной Gradle-конфигурацией с явно отключённой подписью только для этой сборки; производственная проверка наличия паролей не удалена. Unsigned APK нельзя установить до подписания. Debug APK подписан отладочным ключом и не является обновлением ранее подписанного релиза. Для окончательного Android-релиза требуется исходный ключ и его пароль.

Установщик Windows не имеет Authenticode-подписи издателя. Сам упакованный EXE запускался и прошёл runtime smoke. Установка/удаление, firewall lifecycle и замена установленного пользовательского экземпляра не выполнялись. Для независимой проверки установленного приложения нужен отдельный Windows-профиль или виртуальная машина.

## Повторение проверки

Из Android-каталога: `.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`. Для устройства: выбрать работоспособный эмулятор через ANDROID_SERIAL и выполнить `.\gradlew.bat :app:connectedDebugAndroidTest`. HostConnectionTest без отдельного тестового хоста пропускается намеренно.

Из Windows-каталога: `npm test`, `npm run lint`, `npm audit`, `npm run electron:build`. Для интеграции с Android установить debug APK и androidTest APK на отдельный эмулятор, задать AETHER_ANDROID_SERIAL и запустить `node test/runtime-smoke.cjs`. Дополнительный тест создаёт временный профиль хоста и конфигурацию подключения, проверяет реальный мобильный менеджер и удаляет тестовые файлы.

База уязвимостей: https://osv.dev/ . Результаты npm сохранены в audit-final-200.json; Android — android-osv-200.json. Логи сборок и тестов находятся в корнях соответствующих проектов с суффиксом 200.log.
